[Q]
id: AUT-001
domain: 6
type: SINGLE
text:
In a controller-based network, which interface does an application use to communicate with the SDN controller?
options:
A) Southbound API
B) Northbound API
C) Eastbound API
D) Console port
answer: B
explanation:
Northbound API: tra controller e applicazioni/script (tipicamente REST con JSON). Southbound API: tra controller e dispositivi di rete (es. NETCONF, RESTCONF, OpenFlow, OpFlex, SSH/CLI). Eastbound/westbound collegano controller tra loro.
reference: Exam topic 6.2 - Compare traditional networks with controller-based networking
[/Q]

id: AUT-002
domain: 6
type: DRAG
text:
Match each network plane to the function it performs.
items:
Forwarding frames and packets based on tables => Data plane
Building routing tables with OSPF and calculating STP topology => Control plane
Configuring and monitoring devices via SSH and SNMP => Management plane
explanation:
- Data plane: inoltro effettivo del traffico (switching, ACL, NAT, incapsulamento)
- Control plane: decisioni su come inoltrare (protocolli di routing, STP, ARP)
- Management plane: gestione del dispositivo (SSH, SNMP, Syslog, NTP, API)
Nell'SDN il control plane viene in buona parte centralizzato nel controller.
reference: Exam topic 6.1 - Explain how automation impacts network management / 6.2 SDN planes
[/Q]

A REST API call returns HTTP status code 401. What does this code indicate?
options:
A) The request succeeded and a new resource was created.
B) The client is not authenticated or the credentials are invalid.
C) The requested resource does not exist.
D) An internal error occurred on the server.
answer: B
explanation:
Codici HTTP da conoscere:
- 2xx successo: 200 OK, 201 Created, 204 No Content
- 4xx errore client: 400 Bad Request, 401 Unauthorized (autenticazione mancante/errata), 403 Forbidden (autenticato ma senza permessi), 404 Not Found
- 5xx errore server: 500 Internal Server Error, 503 Service Unavailable

[Q]
id: AUT-005
domain: 6
type: SINGLE
text:
Refer to the exhibit. Which JSON data type is the value of the "interfaces" key?
exhibit:
{
  "hostname": "R1",
  "uptime_days": 42,
  "interfaces": [
    {"name": "GigabitEthernet0/0", "enabled": true, "mtu": 1500},
    {"name": "GigabitEthernet0/1", "enabled": false, "mtu": 1500}
  ]
}
options:
A) Object
B) Array
C) String
D) Boolean
answer: B
explanation:
In JSON le parentesi quadre [ ] delimitano un array (lista ordinata); le graffe { } un oggetto (coppie chiave:valore). Qui "interfaces" è un array di oggetti.
Tipi JSON: string ("R1"), number (42), boolean (true/false, minuscolo e senza virgolette), null, object, array.
reference: Exam topic 6.7 - Recognize components of JSON-encoded data
[/Q]

Which two are architectural constraints of REST?
options:
A) Stateless client-server communication
B) The server stores each client's session state between requests
C) Cacheable responses
D) Mandatory use of XML encoding

[Q]
id: AUT-012
domain: 6
type: SINGLE
text:
In a software-defined fabric such as Cisco SD-Access, what is the underlay?
options:
A) The virtual network of tunnels (for example VXLAN) built between fabric devices
B) The physical network and the IP routing that provides connectivity between fabric devices
C) The set of policies applied by the controller
D) The northbound API of the controller
answer: B
explanation:
Underlay: rete fisica (switch, link) e il routing IP che li collega (es. IS-IS o OSPF). Overlay: rete logica costruita sopra con tunnel (VXLAN nel data plane, LISP nel control plane per SD-Access). Fabric: l'insieme di underlay + overlay gestito come un'unica entità.
reference: Exam topic 6.2.a - Overlay, underlay, and fabric
[/Q]
